# Manual test: Grid Network Designer (v0.5, D6)

Run with `pip install -e ".[dev,grid]"` (dss-python installed) and `python -m app`.
Every value typed below is a test input, not equipment data (rule 24: the designer
never invents a value). Tick each step; a step passes only if everything listed under
it happens.

The steps follow `scratch/phase5/d6_walkthrough/walk.py`, which drives the same steps
in the real window with mouse and key events
(`python scratch/phase5/d6_walkthrough/walk_main.py <out folder>` from the repository
root; it prints PASS/FAIL per step and writes screenshots and `walk.json`).
The script cannot open native file dialogs, so for step 18 it calls the slots that
those dialogs call.

## A. Build a small design

1. **Designer tab and empty state.** Click the *Designer* tab.
   - The canvas says "No grid design open" with *New Grid Design…* and *Open .dss as
     Design…* buttons; the library says to create or open a design first.
   - *Run* (toolbar and *Grid > Run Power Flow*) is disabled.
2. **New Grid Design.** *File > New Grid Design…*.
   - OK stays disabled until a name *and* a base frequency are typed (the frequency
     field is empty: there is no default).
   - Type `demo`, `60`, tick *Start with a source bus and a 3-phase source*, keep
     `sourcebus`, type kV `12.47`, R1 `0.1`, X1 `1.0`, R0 `0.1`, X0 `1.0`. OK stays
     disabled while any of them is empty.
   - OK: the canvas shows the bus bar `sourcebus` with the source under it; the status
     bar says `demo: 1 buses, 1 elements`.
3. **Click-to-place a bus.** Click *Bus* in the library, then click the canvas.
   - A bus `b1` appears at the click, on a grid point (Snap on); the tool goes back
     to Select and `b1` is selected.
4. **Branch tool.** Click *Line* in the tool bar, click `sourcebus`, then `b1`.
   - After the first click a dashed blue line follows the pointer; after the second
     a line `l1` joins the two bus bars and is selected. Esc leaves the tool.
5. **Drag a shunt onto a bus.** Drag *Load* from the library onto `b1`.
   - Load `ld1` appears under `b1`, connected by a grey stub, with a red badge (kW and
     kvar not set).
6. **Drag a bus; a shunt off a bus is refused.** Drag *Bus* onto empty canvas: bus
   `b2` appears there. Drag *Capacitor* onto empty canvas.
   - No capacitor is added; the status bar says to drop it onto a bus.
7. **Values a new element needs.** Click *Switch* in the tool bar, click `b1`, then
   `b2`.
   - A popup asks for R (ohm), empty, "required"; nothing is added until it is typed.
     Type `0.0001`, Enter: switch `sw1` joins `b1` and `b2` (filled square).
8. **Line code and the properties panel.** Click *Line code* in the library.
   - `lc1` is added, listed under *Line codes in this design* and selected; the
     properties panel shows R/X/C matrix fields with red "… not set" text under them.
   - Type the R matrix `0.3 0.1 0.1 0.1 0.3 0.1 0.1 0.1 0.3`, X matrix
     `0.6 0.2 0.2 0.2 0.6 0.2 0.2 0.2 0.6`, C matrix `3 -1 -1 -1 3 -1 -1 -1 3`
     (Enter after each): the red text under each goes away.
9. **Badges, status bar, Run disabled.** Look at the canvas and the status bar.
   - Elements with errors carry a red "!" badge (`ld1`, `l1`); the status bar shows
     the error count in red; hovering *Run Power Flow* says "The design has N
     error(s) (see the Console)". Clicking the error count shows the Console with the
     list.
10. **Fill values from the panel.** Select `ld1`: type kW `900`, kvar `300`. Select
    `l1`: choose linecode `lc1`, type length `500`.
    - The badges go away and the error count drops to 0.

## B. Edit

11. **Select.** Click `b1`: it turns orange. Ctrl+click `ld1`: both are selected.
    Click empty canvas: nothing is selected. Drag a rubber band around everything:
    everything is selected ("7 selected").
12. **Move and undo.** Select `b2` and drag it.
    - It moves in whole grid steps, the switch follows it, and *Edit* shows
      "Undo Move bus.b2" (one step for the whole drag). Ctrl+Z puts it back; Ctrl+Y
      moves it again.
13. **Rotate, delete.** With `b2` selected press R: the bar turns vertical. Ctrl+Z.
    Press Del: `b2` and the switch on it disappear (one undo step). Ctrl+Z: both are
    back.
14. **Rename.** Select `b1`, press F2, type `main`, Enter.
    - The bus is now `main`, still selected; `l1` and `sw1` still connect to it.
15. **Switch.** Double-click `sw1`.
    - It is drawn open (dashed red branch, empty red square); double-click again
      closes it.
16. **Pan and zoom.** Wheel zooms around the pointer; middle-drag, right-drag and
    Space + left-drag pan; *Fit* shows the whole design; the zoom % follows.

## C. Run, files

17. **Run.** With 0 errors and dss-python installed, *Run Power Flow* is enabled
    (also *Grid > Run Power Flow* and the main tool bar *Run* while the Designer tab
    is shown). Click it.
    - The status says "Finished: converged …, losses … kW"; the Console lists the
      totals.
18. **Save, export, open.** *File > Save Design* asks for a file name the first time
    (`demo.qgrid`); the `*` after the counts goes away. *File > Export .dss…* writes
    `demo.dss` with `SetBusXY` lines for the bus positions. *File > Open Design
    (.qgrid)…* on `demo.qgrid` gives the same design back (no undo history).

## D. Large feeder and the grid view

19. **Open .dss as Design.** *File > Open .dss as Design…*, choose
    `tests/fixtures/grid/ieee123/IEEE123Master.dss`.
    - The status says "Opened ieee123 as a design: 132 buses, 126 lines, 8
      transformers"; Fit shows the whole feeder; 0 errors.
20. **Smooth pan and zoom (S1).** Pan around and zoom in and out quickly over IEEE 123.
    - No visible stutter (S1 measured ~60 fps on the reference laptop).
21. **Smooth drag.** Drag a bus of IEEE 123 around for a few seconds.
    - The bus and its lines follow the pointer without lag; one undo step.
22. **Edit as Design.** In the *Grid* tab open `tests/fixtures/grid/ieee13/IEEE13Nodeckt.dss`,
    then click *Edit as Design* (top right of the drawing).
    - If the current design has unsaved changes you are asked first. The Designer
      tab opens with an unsaved copy `ieee13nodeckt`; the Grid tab still shows the
      feeder and the .dss file is unchanged (rule 28).
23. **Run follows the tab.** With the Designer tab shown, the main tool bar *Run* and
    *Grid > Run Power Flow* are enabled exactly when the designer's Run is.

How steps 20 and 21 were measured: mouse-move or wheel events every 5-8 ms from a
precise timer (a fast mouse), frames counted from `frameSwapped`; S1 measured 59-60 fps
with the same 60 Hz display. "Glyphs hidden" is the same input with no bus, element or
branch drawn: what the main window itself reaches on this machine. With background
load (22-35 % CPU from other programs) the numbers fell to pan 39 / zoom 23 / drag 31
fps, but the glyphs-hidden baseline fell just as far (40 / 29 fps), so the drop is the
machine, not the designer canvas.

Found and fixed while running this checklist:
- Dragging on IEEE 123 first ran at about 20 fps: every move redrew every row, and
  QUndoStack re-sent every undo signal on each merged move. Moves and rotations now
  update only the glyphs they touched and the lines drawn from them, and undo state is
  sent to QML only when it changes (slot about 1.5 ms).
- A run could fail with "grid runner process exited with code 0" when the child sent
  its result and exited between two pipe polls (core/blocks/process.py); the parent
  now reads the pipe once more before calling the child dead
  (tests/core/blocks/test_process.py).
